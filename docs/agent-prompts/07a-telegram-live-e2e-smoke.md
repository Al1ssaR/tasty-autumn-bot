# Codex Prompt 07a — live Telegram E2E smoke-test

Telegram transport уже реализован, автоматические тесты проходят, commit создан.

На текущем этапе НЕ изменяй архитектуру и НЕ переходи к LLM.

Пользователь:

1. исправил локальный `.env`, чтобы `TELEGRAM_BOT_TOKEN` был записан без пробелов вокруг `=`;
2. отправил реальному боту `@vkusnaya_osen_support_bot` одно обычное текстовое сообщение.

Нужно выполнить финальный live end-to-end smoke-test Telegram intake.

## Проверка

1. Убедись, что `TELEGRAM_BOT_TOKEN` доступен приложению.

Не выводи значение token.

2. Запусти необходимые Docker Compose services.

3. Проверь безопасный:

`php artisan telegram:check`

или эквивалентную реализованную команду.

`getMe` должен завершиться успешно.

4. Запусти polling worker так, чтобы получить отправленный пользователем реальный Telegram update.

Допустимо использовать `--once`, если сообщение уже находится в очереди Telegram.

5. После обработки проверь непосредственно PostgreSQL.

Подтверди, что:

- найден или создан `telegram_participants`;
- существует ровно одно соответствующее incoming `messages`;
- сохранён реальный `telegram_update_id`;
- сохранён реальный `telegram_message_id`;
- `author_type = participant`;
- `delivery_status = not_applicable`;
- исходный пользовательский текст сохранён без изменения;
- `support_ticket_id IS NULL`, поскольку открытого обращения нет;
- `BotDecision` для сообщения отсутствует, поскольку LLM ещё не реализована.

6. Повтори polling после обработки либо иным безопасным способом проверь idempotency.

Уже обработанный Telegram update не должен создавать второе сообщение.

Не пытайся искусственно возвращать update через Telegram API, если Telegram уже подтвердил его offset.

Database UNIQUE constraint остаётся основной гарантией повторной доставки после рестарта.

7. Не отправляй пользователю содержательный ответ.

LLM ещё не подключена.

8. Не выводи:

- bot token;
- полный Telegram API URL;
- полный сырой Telegram payload;
- секреты `.env`.

## После проверки

Корректно останови тестовые контейнеры, сохранив PostgreSQL volume.

Если никаких изменений кода не потребовалось:

- НЕ создавай пустой commit;
- НЕ изменяй файлы только ради commit.

Если live smoke-test обнаружил реальный дефект:

- исправь минимально;
- повтори необходимые автоматические и live проверки;
- создай отдельный commit на русском языке в стиле проекта.

`git push` не выполняй.

## Финальный отчёт

Сообщи:

1. успешен ли `getMe`;
2. получен ли реальный incoming update;
3. создан/reused ли participant;
4. создано ли incoming message;
5. корректны ли Telegram identifiers;
6. сохранён ли исходный текст без изменения;
7. отсутствуют ли ticket и BotDecision;
8. возник ли duplicate;
9. потребовались ли изменения кода;
10. если был commit — его hash и сообщение.

Не переходи к LLM.
